## 二、管线断点（按数据流顺序）

### 写入段 ⚠
| 编号 | 断点 | 位置 | 现状 |
|------|------|------|------|
| B1 | **promote 直通总库**（无隔离带/无三闸） | store.ts `promoteToProject` | LLM 一轮判生即 INSERT；仅文本精确全等去重 |
| B2 | **对话原文 is_active=1 直写总库** | store.ts `saveConversationTurn` | 本应走"分隔带"（审计可见/检索不可见） |
| B3 | **会话历史仅存内存** | buffer.ts `SessionMemoryBuffer` | 进程重启即丢；违背"都应落库"意图 |
| B4 | **同轮消息双通道重复反思** | autoProcessor.ts | saveConversationTurn + buffer 双入口喂同一内容 |
| B5 | mood 前缀拼正文 | saveConversationTurn | `[mood: …]用户:…` 污染嵌入 |
| B6 | digest 无 per-project 锁 | digest.ts | 多库共享消化节奏 |

### 反思段 ⚠
| 编号 | 断点 | 后果 |
|------|------|------|
| A1 | **promote 产物 category 硬码 `session_promoted`** | 语义层被假类别覆盖；星图 category 星座挤爆（LobeHub 盘 207/341=60%） |
| A2 | Full/Lite 反思 prompt 缺 category 赋义段（Anima 有） | 两盘反思产物无语义类别 → A1 只能硬码；三仓同步历史事故 |
| A3 | `classifyMemTypeLLM` 孤儿（autoClassify 未接线） | 主写入路径不经分拣；"先分四类"只在反思侧成立 |

## 四、修复方案（已对齐，按依赖序）

### 第一波（引擎，一处函数为主）
1. **分库三带**（用 source+is_active 表达，不加表）：总库 / `conversation_log` 带（is_active=0）/ `session_ephemeral` 带（is_active=0）
2. **promoteToProject 三闸**：密度（>240 字或低信息密度拒）/ 归属（跨盘专名出现即隔离）/ delta（与库存 cosine>0.9 近重复拒）+ category 交 LLM（出 A1 硬码）
3. **saveConversationTurn 分隔带化** + mood 前缀入 metadata
4. buffer 落库（session_ephemeral 带）+ autoProcess 去双通道
5. digest per-project 锁；saveMemory 接 autoClassify
6. 反思 prompt 补 category 赋义（回灌 Anima 已验证规则）
7. 三仓 sync → build → dist 三实例 → 重启（托盘链）
