## 二、成因链（一页读完）

```
设计意图（Claude 方式落实）:
  入站 → 四类封闭 memType（子分类自由不设限）→ 总库
      ↘ 会话滚动(临时层，应落库不进总图)

实际代码（三处旁门造成 P1-P8）:
  A. promoteToProject      → category 硬码 'session_promoted'        (P1)
  B. saveConversationTurn  → 对话原文 is_active=1 直写总库            (P2/P6)
  C. buffer                → 纯内存 + LLM 单轮判生直写总库            (P3/P4)
  D. autoProcessor         → 双通道重复反思                           (P7)
  E. digest/saveMemory     → 无 project 锁 + autoClassify 缺线        (P5/P8)

数据成灾现场（LobeHub 盘实证）:
  8/23 16:33 单批 189 条 promote 尖峰
  session_promoted 类别 207 条（占盘 60%）
  custom-project::conversation 41 条，中位 1203 字（最长 2850）
  AIRI 名字内容 11 条进 lobehub/reflect 库（PR#1957/五层分工等旧闻）
  → 星图: LobeHub 域巨团糊（P1+P2 主料），AIRI 域反而干净
    （Anima 版反思带 category 赋义规则，这是两盘图质差异的根源）
```

**为什么 AIRI 盘是好的**：Anima 引擎的 reflectDriver 有"情感归位规则"（反思时给 category 赋义），加上 AIRI 分库 CASTALIA_PROJECT=airi 单库结构简单；Full/Lite 同源缺这一段，反思产物全走硬码旁门。
