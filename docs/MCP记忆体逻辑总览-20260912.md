# Castalia MCP 记忆体逻辑总览（2026-09-12）

> 定位：把"一个 MCP 记忆体到底怎么工作"从头到尾讲清楚——**现状是什么**（含已知断点），
> 而不是"应该是什么"。断点编号沿用《管线全景报告》B/A/F 系列。
> 全部依据源码与运行库实测；三仓同源（Lite/Full/Anima 差异单独标注）。

## 一、两套维度 + 一张表，先立骨架

每条记忆（`memory` 表一行）有两组互相独立的分类：

```
type(性质维)        : episodic | semantic | entity | preference     ← "这是什么性质的东西"
mem_type(用途维)    : user | feedback | project | reference | general ← Claude 四类+兜底,决定它存到哪个目录库
category(语义维)    : 自由字符串(conversation/milestone/identity/emotional/milestone/decision/mistake...)
                      ← 不设白名单,交给 LLM 赋义;是星图星座层的分组键
tier(等级维)        : critical | standard | temporary               ← critical 永不衰减/临时有 TTL
```

**物理落盘（memdir 分库）**：`memory/<project>/<mem_type>/memory.sqlite` —— 用途维**就是目录结构**，
四类目录各自一个库文件；跨 project 全球指令/项目注册表在 `global.sqlite`；向量在 `vec_memory`（同一库文件内）。

正交关系举例：一条"用户纠正我解卦错了" = `type=episodic`（事件）× `mem_type=feedback`（纠正用途，落 feedback
目录库）× `category=mistake`（LLM 赋的语义标签）。三者可同时存在，谁也不是谁的子集。

## 二、三条写入通道（现状）

### 通道①：对话自动流（autoProcessor，LobeHub/AIRI 每轮对话走这条）
```
一轮对话(用户消息+AI回复)
 ├→ saveConversationTurn ──→ INSERT memory(source='conversation_log', category='conversation',
 │                                        mood 前缀拼正文, is_active=1)   ⚠ B2: 直写总库,应走分隔带
 └→ getBuffer(project,sessionId).onNewMessage  (⚠ B3: SessionMemoryBuffer 纯内存)
      │ 满 5 轮 或 4000 token(双阈值,互斥锁 isExtracting)
      ▼
   runIncrementalReflection(triage 通道 LLM)  ← 输入: 最近10条消息 + 旧滚动快照 + 身份白名单
      输出 JSON: { sessionMemory, promoted[], identity{add/update/remove}, preferences[] }
      ├→ sessionMemory → upsertSessionMemory(滚动覆盖一行, session_id 隔离)
      ├→ promoted     → promoteToProject ──→ 直接 INSERT 总库            ⚠ B1: 无闸
      ├→ 身份 CRUD    → applyIdentityActions(幻觉 id 白名单拦截, entity 表)
      └→ 晋升成功 → deleteSessionFragments(清 source='session_memory' 的旧行,"晋升即删")
```

### 通道②：显式工具调用（harness/管理员经 MCP 工具，共 32 个）
- 层1 只读检索：`memory_search`（标签LIKE→向量KNN 双段式,decay 分级评分）/ `fact_search` / `memory_graph` / `context_get`（组装注入包：近期+相关+经验沉淀+事实+偏好）
- 层2 写入运维：`memory_save`（**⚠ A3 没接 autoClassify,mem_type 全靠调用方传**）/ `memory_update`（reclassify 改文/类）/ `memory_delete`（软删 is_active=0）
- 层3 反思：`reflect_auto`(日常消化)/`reflect_deep`(全库校准)/`reflect_all`(联邦跨库)/`reflect_apply`(回执审计)
- 层4 分库管理：`project_list/create`、`instruction_save/list/delete`（global 库 L1/L2 层指令）

### 通道③：反思消化（digest.ts，事件驱动）
`auto_process` 每轮顺手 `maybeDigest`（冷却 + 未消化计数）→ `runDigest` 批量提取
（⚠ B6：热闸无 per-project 维度，多库共享节奏）。

## 三、三通道 LLM 与密钥

| 通道 | 用途 | 配置来源 |
|------|------|---------|
| triage(LLM1) | 入站分拣 classifyMemTypeLLM / 增量反思 / 深度反思提示 | reflect-config.json `triage.*` |
| reflect(LLM2) | 日常/深度/整合 reflection | `reflect.*` |
| embedding | 1024d 向量（Yuan-EB :11436 或云端） | `embedding.*` |

api_key 不落 json——`keys.enc`(AES-256-GCM, per 盘独立) 解密注入 env；优先级 env > keys.enc > config。
configLoader 必须是入口第一个 import（ESM 副作用时序，坑 13）。

## 四、检索与注入（消费侧）

```
memory_search(project, query)
  ① 标签/文本 LIKE → computeScore(0.65×一致性[clamp 0.85] + 0.35×decayFor)
     decayFor: critical→永不衰减 / 时效类→10天半衰 / 其余→30天半衰
  ② 未命中 → 向量 KNN(vec0 虚拟表, topK×8 候选) → 同评分公式
  ③ 权重: ×(0.5+importance) ×tierBoost(critical 2.0) ×accessBoost(≤1.5)
注入层(context_get / memory_context):
  系统级 L1(工具描述) → 会话相关 L2(被动召回) → 素材 L3(context_get 拼 harness)
  反思/约束: ABSOLUTE PROHIBITIONS(代码/路径不入库), 四类白名单, 相对时间必须转绝对日期
```

已知消费侧症状（数据层传染）：LobeHub 盘被 207 条假 category + 长文污染 →
检索旧闻霸榜、topK 稀释；修复 B/A 断点后检索代码**零改动**自愈。

## 五、联邦（Full/Anima 独有，Lite 无）

- 引擎层：`FEDERATION_DIRS`（Hermes/LobeHub/AIRI 三盘路径）→ `memory_search_all` 跨盘只读检索（去重合并 by score）

## 七、生命周期总表（一条记忆的一生）

```
诞生
 ├ 路径A(对话): auto_process → conversation_log 行(B2 直写) 或 buffer→增量反思→promote(B1 无闸)
 ├ 路径B(工具): memory_save(调用方给 mem_type; A3 未接分拣) / 反思产物(promoteToProject)
 存在
 ├ 被检索 → accessed_count++ → 热度升格(HEAT_PROMOTE_THRESHOLD≥5 次: temporary→standard)
 ├ 被反思: reflect_deep 全库校准(merge/软删/重分类); reclassify 改文须删旧向量等重嵌
 ├ TTL: tier='temporary' 且 expires_at 过期 → 清理
 死亡
 ├ 软删 is_active=0(检索/KNN 第二段滤掉; 残 vec 占 KNN 候选位无害)
 └ critical 兜底: 反思有"恢复误删 critical"逻辑(restore lostCritical)
```

## 八、对照:这套设计里已经断掉的(现状清单)

| 断点 | 段 | 症状 |

| B1 promote 无三闸/无隔离带 | §二通道① | LLM 一轮判生直写总库 |
